## 2. 起動方法

### 必要なもの
- .NET 10 SDK

### Visual Studio から起動する
1. `StaffNavi.sln`（または `StaffNavi.slnx`）を開きます。
2. F5 キー（または「デバッグの開始」）で起動します。

### コマンドで起動する
```powershell
cd StaffNavi
dotnet run
```
起動したら、ブラウザで http://localhost:5037 を開きます。

## 4. 操作の流れ（デモの進め方）

初期状態では、架空のスタッフ36名（うち10月の勤務32名）・5つのSS・10件の受注について、次のデータが取込済みです。

- **タイムシート**：2025年12月〜2026年10月就業分（10月分は要確認データが未補正のまま）
- **給与計算書**：2026年1月〜10月支給分（＝2025年12月〜2026年9月就業分）

1. **タイムシートを取り込む**
   「CSV取込」画面で `タイムシート_202610_横浜港北セルフSS.csv`（10月から始まったSSのA勤・B勤）をダウンロードして取り込みます。10月の勤務表に受注が追加されます（受注ごとのファイルを何回かに分けて取り込める）。
2. **勤務表で確認・補正する**
   要確認（赤色の行）の「補正」ボタンから勤務内容を直します。補正理由の入力は必須です。10月分には次の要確認データがあります。
   - 終業の打刻漏れ（実データのタイムシートにもある、終業が空欄の行）
   - 休憩不足、1日12時間超の勤務
   - **掛け持ち**：2つのSSの夜間に同じ日に入っていて勤務時間が重複／日勤のあと別の受注の夜間に入り、同日の合計が8時間超
   - 退職日（10/15）より後の勤務
3. **補正履歴を確認する**
   補正前・補正後の差分を確認できます。誤った補正は取り消せますが、記録は削除されずに残ります。
4. **スタッフナビゲーターに戻す**
   「提出資料出力」から、補正後の勤怠を **勤怠データCSV（取込用）** として、スタッフ×受注ごとに出力します。
5. **給与計算書を取り込む**
   「CSV取込」画面で `26.11支給給与計算書.csv`（10月就業分。デモでは本システムの試算値で作成）をダウンロードして取り込みます。賃金台帳の11月が「試算」から「確定」になります。
6. **賃金台帳を確認する**
   1月〜12月（支給月）を横に並べた、先方のExcelと同じ様式で確認します。
7. **提出用資料を出力する**
   「提出資料出力」で帳票を選び、印刷またはPDFで出力します。補正した箇所に※印を付けるかどうかを選べます。

### 取り込めるCSVの形式（いただいた実データと同じ）

1行目の項目名で種類を自動判別します。文字コードは Shift_JIS（スタッフナビゲーターの出力のまま）・UTF-8 のどちらでも読めます。1ファイル20MBまで。

| CSVの種類 | 実データの例 | 項目 |
|---|---|---|
| タイムシート | タイムシートA勤.csv | スタッフ番号、受注番号、就業日、就業データ番号、出欠状況、始業時刻、終業時刻、休憩時間（行末のカンマも可） |
| スタッフ全データ | staff 全データ_26.10.29時点.csv | 202項目のうち、ｽﾀｯﾌ番号、ｽﾀｯﾌ区分、氏名(ｶﾅ)、氏名(漢字)、性別、生年月日、入社日、退職、退職日、雇用形態、各保険の加入状況・等級、介護保険、税区分、扶養家族人数、住民税(7月以降)、１日あたり有給時間 |
| 給与計算書 | 26.10支給給与計算書.csv | 76項目（ｽﾀｯﾌ番号〜差引支給額、支払日、支払方法）。支払日から支給月を判断 |

- 実データの3ファイルで、読込・チェックができることを確認済みです（確認はリポジトリ外の一時フォルダで行い、確認後に削除しました）。
  - スタッフ全データ：10,112行のうち10,111件を取込（氏名が空欄の1行は警告を出して読み飛ばす）
  - タイムシートA勤・B勤：各29件。終業の打刻漏れ（A勤2件・B勤1件）を要確認として検出
  - 給与計算書：2,589件。全件「総支給額－総控除額＝差引支給額」を確認
- タイムシートの受注番号は「設定」画面の受注一覧に登録が必要です（デモでは架空の受注を登録済み）。

### 前払い（給与前払い）のデモ（2026/11 追加）

STEP2以降の検討用に、スタッフが働いた分の一部を給料日前に受け取れる「前払い」の仕組みを追加しました。前払いの原資は導入企業（スタッフの雇用主）の資金で、システムは申請の受付・勤務実績にもとづく審査・振込データの作成を行います。

| 画面 | URL | 内容 |
|---|---|---|
| スタッフ用アプリ（スマホ） | `/App/Login` | スタッフを選んでログイン（またはスタッフ番号＋暗証番号 `1234`）。今すぐ受け取れる金額・今月の勤務・申請・履歴 |
| 前払い状況 | `/Advance` | 申請一覧（3秒ごとに自動更新・新しい申請を通知）、承認・却下、本日振込分の振込データ（全銀フォーマット）作成、スタッフ別の前払い可能額、スタッフ用アプリのQRコード |
| 前払いの条件 | `/Advance/Settings` | 上限（働いた分の％）、最低申請額、申請回数、振込手数料と負担者、自動承認の金額、当日振込の締め時刻 |
| サービス運営 | `/Advance/Service` | 他社にもサービスとして提供する場合の運営画面のイメージ（他社の数値は架空の想定値） |

- **前払い可能額**＝前日までの勤務から計算した働いた分（時給×時間＋深夜・残業の割増。勤務表と同じ時間区分の計算）×上限％ − 申請済みの額。打刻漏れの日は確定するまで含めません。
- 当月の勤務は、デモではタイムシートと同じ作り方の架空データを「日々の勤怠の速報」として使います（本番ではスタッフナビゲーターから日々出力したタイムシート等を取り込む想定）。
- 前払いした額は、賃金台帳の **速払金** に自動で反映されます（就業月の翌月支給分）。
- 振込データは全銀協規定フォーマット（総合振込・120バイト固定長・Shift_JIS）。銀行・口座はすべて架空です。
- **お打ち合わせ当日の朝に「設定」→「デモデータの初期化」を行うと**、当月分の申請履歴が当日までの日付で作り直され、承認待ちの申請（2件）も当日分として表示されます。
- 進め方の例：前払い状況の画面をスクリーンに表示 → QRコードを参加者のスマホで読み取ってもらう → 申請すると管理画面に通知が出る → 2万円を超える申請を承認 → 振込データを作成 → 賃金台帳の速払金を確認。

## 5. 実データに合わせた点（2026/11 更新）

### 5-1. 受注ごとの勤務表・掛け持ち
- スタッフナビゲーターでは、SSの勤務帯（A勤・B勤・夜間など）ごとに受注が分かれ、勤務表（実績）も受注ごとに作られます。本システムも **スタッフ×受注ごとに勤務表を作成**し、スタッフ単位の合計も表示します（出勤日数は同じ日を1日と数える）。
- 1人のスタッフが複数のSS・受注を掛け持ちしている場合、**同じ日の勤務時間の重複**や**同日の合計労働時間が8時間超**を要確認として表示します。

### 5-2. 日をまたぐ勤務（32:00 表記）
- 先方の勤務表と同じく、夜勤の終業は **24:00 以降（例：22:00-32:00）** で表示・入力します。タイムシートCSVで終業が始業より前の時刻（例：8:00）の場合は、翌日として 32:00 に読み替えます。

### 5-3. 時間区分の計算
先方の勤務表（実績）の計算結果を分析し、同じ結果になるようにしました。

- 深夜は 22時〜翌5時。**休憩は深夜帯から差し引く**。
- 始業から数えて **受注ごとの所定時間** を超えた分を普通残・深夜残とする。
- 例（実データと一致）：22:00-32:00・休憩1:00 → 所定7時間の受注は 基本1:00／普通残2:00／深夜6:00、所定8時間の受注は 基本2:00／普通残1:00／深夜6:00。20:00-32:00 → 基本2:00／普通残3:00／深夜6:00。

### 5-4. 出欠
- 勤務表の出欠の選択肢（出勤・欠勤・有給・半給・特休・時有給・休２・休３・休４）に合わせました。
- タイムシートCSVの「出欠状況」は **0＝出勤** を実データで確認済みです。1以降は選択肢の並び順（1＝欠勤、2＝有給…）と想定しています（**要確認**）。

### 5-5. 賃金台帳
- 先方は、スタッフナビゲーターの出力をもとに **Excelで賃金台帳を手作業で作成**されています（約2,600名分／月）。本システムでは **給与計算書CSVを取り込むだけで、全員分の賃金台帳（1年分）を自動作成**します。
- 様式は先方のExcel「印刷用」シートと同じ項目・並び順です（支給日・対象期間、日数・時間・支給・控除、速払金）。
- 給与計算書の「課税他１〜１０（休業補償など）」は「その他課税」、「非課税他１〜５（保安講習受講など）」は「その他非課税」、「債権差押・紙明細発行料など」は「控除」に合計します。「交通費」は非課税として扱います（**要確認**）。
- 支給日は締日（末日）の翌月25日、土日の場合は直前の金曜日です（実データの支給日 1/23・4/24・7/24・10/23 と一致）。
- 給与計算書が未取込の月は、勤務表から **試算**（受注ごとの単価、社会保険料は等級の標準報酬月額×料率）して「試算」と表示します。

### 5-6. スタッフ情報
- スタッフ番号は実データと同じ7桁の数字です（勤務表では 02003105 のように8桁表示）。
- ｽﾀｯﾌ区分（派・ｱﾙ《有雇･社保無》など）、雇用形態、社会保険・雇用保険の加入状況と等級、介護保険、税区分（甲欄・乙欄）、退職日を取り込みます。

### 5-7. 本開発で決めること・確認すること
- 受注情報（就業先・勤務帯・所定時間・単価）の入手方法（スタッフナビゲーターから出力できる形式）
- 出欠状況のコード（1以降）、就業データ番号が2以上（1日に複数回の勤務）の扱い
- 交通費の課税・非課税の区別、遅早の計算
- 掛け持ちの時間外の扱い（スタッフナビゲーターは受注ごとに計算している）
- 作成した勤怠データCSVを、実際のスタッフナビゲーターで取り込めるか

## 6. デモデータを元に戻す

「設定」画面の **「デモデータを初期化」** を押すと、取込データ・補正履歴・操作ログ・設定をすべて削除し、デモ開始時の状態に戻ります。

データは `StaffNavi/App_Data` に JSON 形式で保存されています（データベースは使っていません。Gitの管理対象外）。
このフォルダを削除しても、次回起動時に初期状態で自動的に作り直されます。
データの形式を変えたときは `LaborRepository.DataVersion` を上げると、古い形式のデータは起動時に自動で作り直されます（サーバの `App_Data` も同様）。
